# Opinion Dynamics

Симулятор динамики мнений (от 2 до 10 000 мнений) на многоуровневом случайном графе с упрямыми вершинами,
учётом весов рёбер и эволюцией рёбер во времени. Ядро написано на C++17, визуализация и
форма запуска — на Python.

## Модель

### Граф

Граф неориентированный и взвешенный, строится по обобщённой модели Эрдёша–Реньи из `n` уровней.
Уровень `i` содержит `Nᵢ` вершин и имеет вероятность связи `pᵢ`:

- ребро между двумя вершинами **одного уровня** `i` появляется с вероятностью `pᵢ`;
- ребро между вершинами **уровней `i` и `j`** появляется с вероятностью `min(pᵢ, pⱼ)`.

Вес каждого ребра — случайное число из `[0, 1)`. Суммарно в графе не более 20 000 вершин,
включая добавленные упрямые.

### Мнения

Мнение каждой вершины — целое число от 0 до `n − 1`, где `n` — число мнений (от 2 до 10 000,
по умолчанию 2). Номера мнений — просто метки, порядка между ними нет.

На каждом шаге для каждой обычной вершины `j` считается доля соседей с каждым мнением `k`,
**только по мнениям, которые есть у соседей**:

```
без весов:  sₖ = (число соседей с мнением k) / (число соседей)
с весами:   sₖ = Σ w(j,u) по соседям u с мнением k / Σ w(j,u) по всем соседям
```

Поэтому время шага зависит от числа рёбер, а не от числа мнений: 10 000 мнений считаются
так же быстро, как 2.

Как доли превращаются в вероятности, задаёт **функция изменения мнений** `g(s)`. В модели одна
функция на все мнения, её выбирают из списка (`s` — доля соседей с мнением):

| Имя | Формула | Параметры | Смысл |
|---|---|---|---|
| `threshold` | `0` при `s ≤ k1`, `(s − k1)/(k2 − k1)` до `k2`, `1` после | `0 ≤ k1 < k2 ≤ 1` | пороговая модель (по умолчанию `k1 = 0`, `k2 = 1`) |
| `moran` | `(1 + δ)·s` у мнения-мутанта, `s` у остальных | `δ ≥ −1`, второй параметр — мнение-мутант (по умолчанию 1) | процесс Морана: мутант копируется в `1 + δ` раз охотнее; `δ = 0` — модель избирателя |
| `polynomial` | `a·sⁿ + b·sⁿ⁻¹ + … + свободный член` | коэффициенты от старшей степени: `3,2,1` = `3s² + 2s + 1` | например `s²` (параметры `1,0,0`) — конформизм, большинство усиливается |
| `exponential` | `a·e^(b·s)` | `a, b` | логит-правило: чем больше `b`, тем сильнее вершина идёт за большинством |

Отдельной линейной функции нет: `a + b·s` — это полином первой степени с параметрами `b,a`.
Например, `1,0` — это `s`, `1,0.05` — `s + 0.05`.

По значениям функции считаются вероятности мнений, которые есть у соседей:
`P(k) = g(sₖ) / Σₘ g(sₘ)`. Отрицательные значения считаются нулём; если все значения нулевые,
вершина сохраняет мнение. Дальше новое мнение выбирается по одному из двух **правил выбора**:

| Правило | Как выбирается мнение |
|---|---|
| **максимум** (`max`, по умолчанию) | кандидат — мнение с наибольшей `P(k)`. Вершина переходит в него с вероятностью `P(кандидата)` («монетка»), иначе сохраняет своё мнение. Если кандидатов с одинаковой `P` несколько, побеждает то, что выше в **списке популярности** (например `5,3,2` — сначала 5, потом 3, потом 2); если ни одного из них в списке нет или список пуст — случайный из них |
| **пропорционально** (`proportional`) | мнение `k` выбирается случайно с вероятностью `P(k)`. Так работали все прогоны до появления правил, файлы без строки `CHOICE_RULE` читаются с этим правилом |

У пороговой функции при правиле «пропорционально» действует классическая схема: мнение 0
получает остаток `1 − Σₖ f(sₖ)`, остальные мнения `k` — вероятность `f(sₖ)`. При двух мнениях
это «мнение 1 с вероятностью `f(s₁)`, иначе 0», как раньше.

**Важно про правило «максимум».** Для возрастающей функции (`s`, `s²`, экспонента, Моран с
небольшим `δ`) кандидат — всегда самое частое мнение среди соседей, а функция влияет только на
шанс монетки. Поэтому меньшинство, в том числе упрямые вершины, не может распространить своё
мнение, пока не станет большинством хотя бы у части соседей. Чтобы изучать захват графа
упрямым меньшинством, используйте правило «пропорционально».

Внутри программы у каждого мнения хранится своя функция, поэтому модель можно расширить
до разных функций для разных мнений без изменения остального кода.

Обновление **синхронное**: все вершины на шаге `t+1` смотрят на мнения шага `t`.
Вершины без соседей своё мнение не меняют.

### Начальные мнения

Начальное мнение есть у всех вершин, включая упрямые. Оно задаётся отдельно для двух групп:

| Группа | Варианты | По умолчанию |
|---|---|---|
| обычные вершины | одно мнение у всех или случайное (равномерно из `0..n − 1`) | мнение 0 |
| упрямые вершины | одно мнение у всех или случайное | мнение 1 |

Поверх групп можно задать мнения отдельных вершин вручную в виде `вершина:мнение`,
например `0:2,5:1`.

Начальные мнения сохраняются в `graph_initial.txt`, поэтому прогон со случайными мнениями
повторяется загрузкой этого файла.

### Упрямые вершины

Упрямые вершины никогда не меняют своё начальное мнение. Задаются двумя независимыми
группами, которые можно использовать одновременно:

| Группа | Что делает | Ограничение |
|---|---|---|
| **Назначить существующие** | делает упрямыми уже существующие вершины графа | без повторов, не больше числа вершин |
| **Прикрепить новые** | добавляет новую вершину степени 1 и соединяет её с выбранной вершиной графа | цели могут повторяться, не больше `min(N, 20000 − N)` |

Для каждой группы вершины выбираются случайно или вручную (номера от `0` до `N − 1`,
где `N` — число вершин в уровнях; ручной ввод в интерактивном режиме — до 100 вершин).
Прикреплённые вершины получают номера после вершин уровней: `N`, `N + 1`, …

### Динамика рёбер

Если включена, то на каждом шаге `t` (отсчёт с `t = 0`) перед обновлением мнений для каждой
пары вершин `(u, v)`:

- если ребра нет — оно появляется с вероятностью `p_add(t)` и получает случайный вес из `[0, 1)`;
- если ребро есть и включено удаление — оно исчезает с вероятностью `p_remove(t)`.

Функции `p_add(t)` и `p_remove(t)` выбираются **независимо** из списка ниже. Результат любой
функции обрезается до отрезка `[0, 1]`.

| Имя (`--add-func`) | Формула | Параметры |
|---|---|---|
| `constant` | `p = a` | `a` |
| `linear` | `p = a + b·t` | `a, b` |
| `polynomial` | `p = c0 + c1·t + c2·t² + …` | `c0, c1, …` (сколько угодно, минимум один) |
| `exponential` | `p = a·e^(b·t)` | `a, b` |
| `saturation` | `p = pmax·(1 − e^(−r·t))` | `pmax, r` |
| `logistic` | `p = pmax / (1 + e^(−r·(t − t0)))` | `pmax, r, t0` |
| `step` | `p = a` при `t < T`, иначе `b` | `a, b, T` |
| `periodic` | `p = a + b·sin(w·t)` | `a, b, w` |

Удаление рёбер работает только при включённой динамике рёбер.

### Воспроизводимость

Один seed определяет весь прогон: граф, случайные начальные мнения и симуляцию. Они берут
случайные числа из трёх независимых потоков `std::mt19937`, выведенных из одного seed, поэтому
включение случайных начальных мнений не меняет ни граф, ни ход симуляции при тех же мнениях.
Поэтому прогон можно повторить двумя способами, и оба дают побайтово одинаковые файлы:

- запустить генерацию с теми же параметрами и тем же `--seed`;
- загрузить `graph_initial.txt` из папки прогона с сохранёнными в нём параметрами.

Веса рёбер сохраняются с полной точностью (17 значащих цифр), рёбра в файле отсортированы.

**C++:**
- компилятор с поддержкой C++17 (GCC 8+, Clang 7+, MSVC 2019+);
- CMake 3.12+;
- для документации кода (по желанию): `doxygen` и `graphviz`.

### Виртуальное окружение Python

Python-зависимости ставятся в виртуальное окружение `venv` в корне проекта, чтобы не засорять
системный Python (в новых версиях Linux `pip install` вне venv вообще запрещён).

Создать окружение (один раз):

```bash
python3 -m venv venv
```

Активировать (в каждом новом терминале перед запуском скриптов):

```bash
source venv/bin/activate        # Linux / macOS
venv\Scripts\activate           # Windows (cmd)
venv\Scripts\Activate.ps1       # Windows (PowerShell)
```

После активации в начале строки терминала появится `(venv)`. Установить зависимости:

```bash
pip install -r requirements.txt
```

Выйти из окружения — команда `deactivate`. Папка `venv/` добавлена в `.gitignore`
и в репозиторий не попадает.

Если `tkinter` не найден (ошибка `No module named 'tkinter'`), установите его системно:

```bash
sudo apt install python3-tk     # Ubuntu / Debian
sudo dnf install python3-tkinter  # Fedora
```

На Windows и macOS `tkinter` обычно входит в стандартную установку Python.

## Сборка

```bash
mkdir build
cd build
cmake ..
cmake --build .
```

Исполняемый файл: `build/opinion_dynamics`. Все `.cpp` из `src/` подключаются автоматически,

## Запуск

Есть три способа: форма, интерактивный режим и batch-режим. Во всех случаях результаты
сохраняются в папку `runs/run_<seed>/` относительно текущей директории запуска.

### Форма запуска (GUI)

```bash
source venv/bin/activate
cd visualization
python run_simulation.py
```

Форма позволяет:
- сгенерировать граф (уровни, число шагов, seed, веса, упрямые вершины) или загрузить
  граф из папки прогона с переопределением параметров;
- задать число мнений, функцию изменения мнений, правило выбора, список популярности
  и начальные мнения (при загрузке каждую из этих групп можно взять из файла или переопределить);
- включить появление и удаление рёбер, выбрав для каждого функцию и параметры
  (формула и список параметров показываются под выбором);
- после завершения сразу открыть визуализацию (она запускается отдельным окном).

Форма вызывает бинарник в batch-режиме; путь к нему по умолчанию `../build/opinion_dynamics`.
Папки прогонов создаются рядом с бинарником: `build/runs/`.
Горячие клавиши: `Ctrl+Enter` — запуск, `Esc` — закрыть.

### Интерактивный режим

```bash
./build/opinion_dynamics
```

Программа задаёт вопросы по очереди:

1. Сгенерировать новый граф или загрузить из папки прогона.
2. **Генерация:**
   - способ: ручной (свои вершины и вероятность для каждого уровня) или общий (одинаковые для всех уровней);
   - число уровней и параметры уровней;
   - упрямые вершины: сначала группа «назначить существующие», затем «прикрепить новые»;
   - динамика рёбер: функция появления, затем (по желанию) функция удаления;
     после ввода параметров печатаются `p(0)`, `p(50)`, `p(100)`, `p(500)` для проверки;
   - число мнений;
   - функция изменения мнений и её параметры (для пороговой — `k1`, `k2`, для полиномиальной —
     степень и коэффициенты от старшей степени, для Морана — `δ` и мнение-мутант);
   - правило выбора и, для правила «максимум», список популярности;
   - начальные мнения обычных и упрямых вершин и, по желанию, мнения отдельных вершин;
   - учёт весов;
   - число шагов и seed (вручную, от 0 до 4 294 967 295, или случайный).
3. **Загрузка:** путь к папке прогона, какой граф взять (начальный или конечный) и использовать ли
   сохранённые параметры. Если параметров в файле нет или вы отказались — они вводятся заново.
   С сохранёнными параметрами начальные мнения берутся из файла графа.

### Batch-режим

Все параметры задаются флагами, вопросов нет. Подходит для скриптов и серийных запусков.

**Генерация графа:**

```bash
./opinion_dynamics --batch \
  --level-vertices "50,30" --level-probabilities "0.2,0.05" \
  --k1 0.05 --k2 0.5 --tmax 300 --seed 42 \
  --stubborn-attach 5 \
  --stubborn-assign 3 --stubborn-assign-mode manual --stubborn-assign-targets "0,10,20" \
  --use-weights \
  --dynamic-edges --add-func logistic --add-params "0.02,0.1,50" \
  --remove-edges --remove-func constant --remove-params "0.001"
```

**Пять мнений со случайным стартом:**

```bash
./opinion_dynamics --batch --vertices 200 --probability 0.05 --tmax 300 --seed 1 \
  --num-opinions 5 --initial-regular random --popularity "3,1" \
  --opinion-func polynomial --opinion-params "1,0"
```

**Загрузка из папки прогона** (параметры берутся из файла, флаги их переопределяют):

```bash
./opinion_dynamics --batch --load-dir runs/run_42 --tmax 1000 --no-weights
```

Начальные мнения при загрузке берутся из файла графа (секция `OPINIONS`), если не задан ни один
из флагов `--initial-…`. Для `graph_final.txt` это мнения после последнего шага, то есть прогон
продолжается с того места, где остановился.

Секция `PARAMS` есть только в `graph_initial.txt`. Для конечного графа параметры задаются флагами:

```bash
./opinion_dynamics --batch --load-dir runs/run_42 --load-graph final --k1 0.05 --k2 0.5 --tmax 300
```

**Все флаги:**

| Флаг | Значение | По умолчанию |
|---|---|---|
| `--batch` | включить batch-режим | — |
| `--level-vertices "N1,N2,…"` | число вершин по уровням | — |
| `--level-probabilities "p1,p2,…"` | вероятности по уровням | — |
| `--vertices N --probability p` | короткая запись для одного уровня | — |
| `--load-dir DIR` | загрузить граф из папки прогона | — |
| `--load-graph initial\|final` | какой граф загрузить | `initial` |
| `--num-opinions N` | число мнений, от 2 до 10 000 | `2` |
| `--opinion-func NAME` | функция изменения мнений: `threshold`, `moran`, `polynomial`, `exponential` | `threshold` |
| `--opinion-params "a,b,…"` | параметры функции | `0,1` |
| `--k1 X`, `--k2 Y` | короткая запись пороговой функции с порогами `k1`, `k2` | `0`, `1` |
| `--choice-rule max\|proportional` | правило выбора нового мнения | `max` (для файлов без правила — `proportional`) |
| `--popularity "5,3,2"` | список популярности для ничьих в правиле `max` | пусто — ничьи случайно |
| `--initial-regular random\|K` | начальное мнение обычных вершин | `0` |
| `--initial-stubborn random\|K` | начальное мнение упрямых вершин | `1` |
| `--initial-opinions "v:k,…"` | мнения отдельных вершин, перекрывают группы | — |
| `--tmax N` | число шагов | `500` |
| `--seed N` | seed генератора симуляции | случайный |
| `--use-weights` / `--no-weights` | учитывать ли веса рёбер | не учитывать |
| `--stubborn-attach N` | прикрепить N новых упрямых | `0` |
| `--stubborn-attach-mode random\|manual` | способ выбора целей | `random` |
| `--stubborn-attach-targets "i,j,…"` | цели при ручном выборе | — |
| `--stubborn-assign N` | назначить N существующих вершин упрямыми | `0` |
| `--stubborn-assign-mode random\|manual` | способ выбора | `random` |
| `--stubborn-assign-targets "i,j,…"` | вершины при ручном выборе | — |
| `--runs-dir DIR` | папка, в которой создаются папки прогонов | `runs` |
| `--quiet` | печатать только папку прогона и итог | выкл. |
| `--dynamic-edges` | включить появление рёбер (нужны `--add-func` и `--add-params`) | выкл. |
| `--add-func NAME`, `--add-params "a,b,…"` | функция появления рёбер | — |
| `--remove-edges` | включить удаление рёбер (нужны `--remove-func` и `--remove-params`) | выкл. |
| `--remove-func NAME`, `--remove-params "a,b,…"` | функция удаления рёбер | — |

Для совместимости со старыми скриптами работают флаги `--stubborn`, `--stubborn-mode`,
`--stubborn-targets` (то же, что `--stubborn-attach…`) и `--p0 X --k Y`, `--remove-p0 X --remove-k Y`
(задают функцию `linear`).

Пример процесса Морана с `δ = 0.5`, как в бинарной модели (мутант — мнение 1 упрямых вершин):

```bash
./opinion_dynamics --batch --vertices 100 --probability 0.08 --tmax 100 --seed 1 --stubborn-assign 3 \
  --opinion-func moran --opinion-params 0.5 --choice-rule proportional
```

Чтобы повторить прогон, сделанный до появления правил выбора, добавьте `--choice-rule proportional`
или просто загрузите его папку: правило читается из файла.

При загрузке файла без секции `PARAMS` обязательны функция мнений (`--k1` и `--k2` или
`--opinion-func`) и `--tmax`.
Неизвестный флаг или неверное значение завершает программу с сообщением об ошибке и справкой.

## Результаты прогона

Каждый запуск создаёт папку `runs/run_<seed>/`. Существующие папки не перезаписываются:
если `run_42` уже есть, прогон с тем же seed попадёт в `run_42_2`, затем в `run_42_3` и так далее.
Точный путь печатается в строке «Папка прогона».

| Файл | Содержимое |
|---|---|
| `graph_initial.txt` | граф до симуляции, начальные мнения и секция `PARAMS` со всеми параметрами запуска |
| `graph_final.txt` | граф и мнения после последнего шага (без секции `PARAMS`) |
| `simulation_log.txt` | параметры, число вершин по мнениям на каждом шаге, все изменения мнений и рёбер, итоговые мнения |

В консоль выводятся статистика графа (вершины, рёбра, упрямые, средняя степень), параметры,
начальное распределение мнений, затем на первых 100 шагах и далее каждые 50 шагов —
сколько мнений осталось, самое частое мнение и число его вершин, число рёбер. В итоге печатаются
пять самых частых мнений.

Чтобы повторить прогон, загрузите `graph_initial.txt` из его папки с сохранёнными параметрами.

## Визуализация

```bash
source venv/bin/activate
cd visualization
python visualize.py ../build/runs/run_42
```

Сверху в окне подписаны функция изменения мнений, правило выбора и число мнений.

**Цвета мнений** одинаковые на всех шагах:
- 2 мнения — серый (0) и красный (1), как раньше;
- до 10 мнений — у каждого мнения свой цвет;
- больше 10 — свои цвета у 9 мнений, которых за прогон было больше всего, остальные серые («прочие»).

Упрямые вершины закрашены цветом своего мнения и обведены чёрным. Легенда справа.

- **До 100 вершин:** окно с графом по шагам. Слайдер выбирает шаг, кнопка Play проигрывает
  симуляцию. В заголовке — номер шага, число оставшихся мнений, самое частое мнение и число рёбер.
  Под графом — доли цветных мнений по шагам, вертикальная линия показывает текущий шаг.
- **Больше 100 вершин:** три графика по шагам — доли цветных мнений (и «прочих»),
  число различных мнений и число рёбер.

Прогоны старых версий (без начальных мнений в файле и с бинарной историей) тоже читаются.

## Эксперименты

Серия прогонов описывается JSON-файлом в `experiments/configs/`: какие флаги общие, какие
перебираются и сколько seed на каждую точку. `sweep.py` запускает все сочетания параллельно
(по числу ядер), считает метрики и пишет одну строку на прогон в `results.csv`:

```bash
source venv/bin/activate
cd experiments
python sweep.py configs/stubborn_capture.json
python plot.py results/stubborn_capture/results.csv \
    --x stubborn_share --y captured --group function --panel choice-rule
```

Результаты попадают в `experiments/results/<имя серии>/` (папка не перезаписывается, повторный
запуск создаёт `_2`, `_3`…), там же сохраняется копия конфига. Папки отдельных прогонов после
подсчёта метрик удаляются, `--keep-runs` их оставляет, `--jobs N` задаёт число потоков.
Seed идут подряд с `seed_start`, поэтому серия полностью воспроизводится.

**Формат конфига:**

```json
{
  "name": "stubborn_capture",
  "binary": "../build/opinion_dynamics",
  "seeds": 50,
  "fixed": {"vertices": 50, "probability": 0.3, "tmax": 500},
  "vary": {
    "stubborn-assign": [0, 5, 10],
    "choice-rule": ["proportional", "max"],
    "function": [
      {"label": "s", "opinion-func": "polynomial", "opinion-params": "1,0"},
      {"label": "moran 0.5", "opinion-func": "moran", "opinion-params": "0.5"}
    ]
  }
}
```

Ключи — имена флагов без `--`, `true` — флаг без значения (`"use-weights": true`).
Если значение в `vary` — объект, это вариант из нескольких флагов сразу, в таблицу пишется его `label`.

**Метрики** (столбцы `results.csv`):

| Столбец | Что значит |
|---|---|
| `num_vertices`, `num_stubborn`, `stubborn_share` | размер графа, число и доля упрямых |
| `distinct_initial`, `distinct_final` | сколько мнений в начале и в конце |
| `consensus`, `consensus_step` | у всех вершин одно мнение (1/0) и первый такой шаг |
| `winner`, `winner_share` | самое частое мнение в конце и его доля |
| `stubborn_opinion`, `stubborn_opinion_share` | мнение упрямых (если у всех одинаковое) и его доля в конце |
| `captured`, `capture90_step` | мнение упрямых у всех вершин (1/0); первый шаг, когда оно у 90% |

`plot.py` усредняет метрику по seed: `--x` — столбец по горизонтали, `--y` — метрика, `--group` —
разные линии, `--panel` — соседние панели. Для метрик из 0 и 1 интервал считается по Уилсону,
для остальных — среднее ± 1.96 стандартной ошибки; пустые значения (например, `capture90_step`
в прогонах без захвата) пропускаются, их число видно в столбце `n` таблицы, которую печатает скрипт.

## Форматы файлов

Все файлы текстовые, токены разделены пробелами или переводами строк.

### Граф (`graph_initial.txt`, `graph_final.txt`)

```
VERTICES 155
STUBBORN 3
3
17
150
EDGES 1189
0 5 0.287298
0 6 0.857518
...
```

Каждое ребро записано один раз (`u < v`) в формате `u v вес`. После рёбер идёт секция
`OPINIONS N` — мнение каждой вершины по порядку (в `graph_initial.txt` начальные, в `graph_final.txt`
конечные). В файлах старых версий этой секции нет.

### Секция PARAMS (в конце `graph_initial.txt`)

```
PARAMS
SEED 42
T_MAX 300
NUM_OPINIONS 5
OPINION_FUNCTION threshold 2 0.05 0.5
CHOICE_RULE max
POPULARITY 2 3 1
INITIAL_REGULAR random
INITIAL_STUBBORN 1
INITIAL_MANUAL 2 0 2 5 1
USE_WEIGHTS 1
DYNAMIC_EDGES 1
ADD_FUNCTION logistic 3 0.02 0.1 50
REMOVE_EDGES 1
REMOVE_FUNCTION constant 1 0.001
```

Функция записывается как `имя число_параметров параметры…`, список популярности — как
`число мнения…`, ручные начальные мнения — как `число пары «вершина мнение»…`.
`INITIAL_REGULAR` и `INITIAL_STUBBORN` — номер мнения или `random`.

Старые файлы тоже читаются: ключи `K1`/`K2` превращаются в пороговую функцию,
`P0`/`K` и `REMOVE_P0`/`REMOVE_K` — в функцию `linear`. Если строк про мнения нет, берутся
2 мнения, правило `proportional`, обычные вершины с мнением 0 и упрямые с мнением 1 —
так старые прогоны воспроизводятся без изменений.

### Лог (`simulation_log.txt`)

```
строки секции PARAMS     по одной на параметр, как в graph_initial.txt
INITIAL_GRAPH_FILE runs/run_42/graph_initial.txt
FINAL_GRAPH_FILE runs/run_42/graph_final.txt

OPINION_HISTORY <T>    затем T строк: рёбер K мнение_1 вершин_1 … мнение_K вершин_K
                       (K — сколько мнений осталось, от самого частого)
OPINION_CHANGES <M>    затем M строк: шаг вершина было стало
EDGE_EVENTS <E>        затем E строк: шаг ADD|REMOVE u v вес
FINAL_OPINIONS <N>     затем N строк: мнение вершины
```

Шаги в логе нумеруются с 1.

## Подбор параметров

- **k1** — порог, ниже которого вершина не принимает мнение 1. Если `k1` больше `1 / средняя_степень`,
  одна упрямая вершина не может повлиять на соседа, и система остаётся в начальном состоянии.
- **k2** — порог, выше которого мнение 1 принимается наверняка. Чем ближе `k2` к `k1`,
  тем резче переход.
- **δ в процессе Морана** — скорость распространения мнения-мутанта. При правиле
  «пропорционально» на графе из 100 вершин с 3 упрямыми 90% вершин получают мнение 1 в среднем
  примерно за 50 шагов при `δ = 0`, за 13 при `δ = 0.5` и за 6 при `δ = 2`; при `δ = −0.5` захвата нет.
- **Правило выбора** — «максимум» быстро приводит граф к локальному большинству и сохраняет
  мнения, которые где-то в большинстве; «пропорционально» оставляет шанс меньшинству и даёт
  захват графа упрямыми вершинами.
- **Число мнений** — при случайном старте с большим `n` у каждой вершины почти все соседи с разными
  мнениями, и на первых шагах много ничьих. Список популярности делает исход ничьих предсказуемым.
- **Веса** — при их учёте влияние соседа пропорционально весу ребра, поэтому слабые связи
  с упрямыми вершинами влияют меньше.
- **Функции рёбер** — динамика проверяется для каждой пары вершин на каждом шаге, поэтому даже
  вероятность `0.001` на графе из 1000 вершин даёт около 500 новых рёбер за шаг.
  Для больших графов берите маленькие значения. Динамика рёбер на больших графах — самая
  медленная часть симуляции (O(N²) на шаг).
- **Число шагов** — 50 для быстрой проверки, 300–500 для большинства экспериментов,
  тысячи — для медленной динамики.
