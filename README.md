# Opinion Dynamics

Симулятор динамики мнений на графе с упрямыми вершинами и эволюцией рёбер.

## О модели

Модель описывает процесс распространения бинарного мнения (0 или 1) по неориентированному
взвешенному графу. На каждом шаге симуляции для каждой обычной вершины `j` вычисляется
доля единиц среди её соседей:

    x_j = c_j / d_j

где `c_j` — число соседей с мнением 1, `d_j` — степень вершины. Затем по кусочно-линейной
функции с порогами `k1 < k2` вычисляется вероятность смены мнения:

    f(x) = 0,                    если x <= k1
    f(x) = (x - k1) / (k2 - k1), если k1 < x <= k2
    f(x) = 1,                    если x > k2

С этой вероятностью вершина переходит в состояние 1, иначе — в 0. Обновление синхронное:
все вершины на шаге `t` видят состояние мира на шаге `t-1`.

Упрямые вершины зафиксированы в состоянии 1 и не меняют мнение никогда.

Если включена динамика рёбер, на каждом шаге `t` вероятность появления нового ребра
пересчитывается как `p(t) = p0 + k * t` с ограничением в [0, 1], и новые рёбра
добавляются к графу (существующие не удаляются).

## Структура проекта

    include/od/
        config/     ManualGenConfig.hpp      — структура конфигурации и валидация
        graph/      Graph.hpp                — класс графа (вершины, рёбра, упрямые)
                    GraphGenerator.hpp       — генерация графа по конфигу
        io/         InputHelpers.hpp         — ввод чисел с проверками
                    GraphIO.hpp              — сохранение/загрузка графа
        model/      DynamicsModel.hpp        — модель мнений (initOpinions, stepOpinions)
                    EdgeEvolution.hpp        — динамика рёбер (linearProbability, evolveEdges)
    src/            — реализации всех модулей
    main.cpp        — точка входа, цикл симуляции

## Требования

- Компилятор с поддержкой C++17 (GCC 7+, Clang 5+, MSVC 2017+)
- CMake 3.10+
- Опционально: CLion или любая IDE с поддержкой CMake

## Сборка

### Через CMake из командной строки

    mkdir build
    cd build
    cmake ..
    cmake --build .

Или, если у вас установлен `make` напрямую:

    mkdir build && cd build
    cmake .. && make

Исполняемый файл появится как `build/opinion_dynamics`.

### Через CLion

1. Откройте папку проекта в CLion: `File → Open`, укажите корень репозитория.
2. CLion автоматически подхватит `CMakeLists.txt` и настроит конфигурацию.
3. Соберите проект: `Build → Build Project` (Ctrl+F9).
4. Запустите: `Run → Run 'opinion_dynamics'` (Shift+F10).

## Запуск

    ./build/opinion_dynamics

Программа интерактивная — задаёт вопросы по очереди и читает ответы из stdin.

### Порядок вопросов

1. **Количество уровней** (1..10000).
2. **Для каждого уровня:**
   - количество вершин на уровне;
   - вероятность появления ребра внутри уровня (0.0..1.0).
3. **Упрямые вершины** — `y` / `n`. Если `y`:
   - сколько упрямых вершин добавить (1..общее число вершин).
4. **Динамика рёбер** — `y` / `n`. Если `y`:
   - начальная вероятность `p0` (0.0..1.0);
   - коэффициент `k` (-5.0..5.0).
5. **Пороги модели мнений:**
   - `k1` (0.0..1.0);
   - `k2` (`k1`..1.0).

После ввода программа генерирует граф, выводит его статистику (число вершин, рёбер,
упрямых, среднюю степень), а затем прогоняет симуляцию на `T_MAX = 500` шагов и печатает
число вершин с мнением 1 каждые 50 шагов и в конце.

## Настройка параметров

`T_MAX` (число шагов симуляции) задано константой в `main.cpp`:

    const int T_MAX = 500;

Измените её и пересоберите проект, если нужна другая длительность симуляции.
Ориентировочные значения:

- 50 — быстрая проверка, что всё работает;
- 500 — большинство экспериментов;
- 5000..10000 — если хотите увидеть медленную динамику (как в оригинальной презентации).

## Что влияет на результат

- **k1** — порог «ниже которого ничего не происходит». Если `k1` больше, чем `1 / средняя степень`,
  одиночная упрямая вершина не может «заразить» своего соседа, и система застревает в
  начальном состоянии. Для графа со средней степенью 30 подходящий `k1` — порядка 0.03 и ниже.
- **k2** — порог «выше которого смена мнения гарантирована». Должен быть строго больше `k1`.
- **p0, k** — определяют, насколько быстро растёт плотность рёбер во времени. При `k = 0`
  динамика рёбер отключена фактически, даже если флаг включён.

## Сериализация графа (API, не подключено в main)

Заголовок `od/io/GraphIO.hpp` предоставляет функции:

    void saveGraph(const Graph& graph, const std::string& filename);
    Graph loadGraph(const std::string& filename);

Формат файла — текстовый:

    VERTICES 155
    STUBBORN 5
    3
    17
    42
    88
    120
    EDGES 1189
    0 5 0.287298
    0 6 0.857518
    ...

Пример использования (можно добавить в `main.cpp`):

    #include "od/io/GraphIO.hpp"
    ...
    od::io::saveGraph(graph, "graph_dump.txt");
    od::graph::Graph restored = od::io::loadGraph("graph_dump.txt");

## Структура сохранения/загрузки

- `saveGraph` обходит все вершины и для каждого ребра `(u, v)` пишет его только один раз —
  при условии `u < v`, чтобы не задваивать неориентированные рёбра.
- `loadGraph` проверяет корректность формата: ключевые слова `VERTICES`, `STUBBORN`, `EDGES`,
  диапазоны индексов, неотрицательность счётчиков. При нарушении бросает `std::runtime_error`
  с понятным сообщением.
